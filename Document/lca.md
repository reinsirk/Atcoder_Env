# 最近共通祖先

[LCA](../Graph/LCA.cpp)は無向森を前処理し、共通祖先・距離・祖先・パス上の頂点を照会します。[使用例](../Examples/lca_example.cpp)を参照してください。重みは辺数として数えます。

## 入力と構築

隣接リストは無向で対称な森、頂点番号は`[0,N)`が前提です。自己ループ・多重辺・閉路を含めません。指定した`root`の成分を先に処理し、その後は最小未訪問頂点を各成分の根にします。空の入力には`root=0`を指定します。

再帰を使わずDFS順と部分木の終了位置を求めます。最大深さHが256以下なら最大9段の祖先表、それより深ければ32頂点ごとのRMQと祖先探索用のLadderを構築します。B=ceil(N/32)とすると、構築はO(N+E+B log(B+1))、保持領域はO(N+B log(B+1))、構築中の追加作業領域はO(N)です。Eは隣接リストの要素数として数えます。浅い森ではRMQとLadderを確保しません。

浅い森の祖先表は、Clangでは頂点ごと、その他のコンパイラでは段ごとに配置します。段ごとの配置では0段目に親配列を連続コピーし、1段目を根で止める形で構築します。その後は前段の添字が必ず有効な頂点なので、深さ判定をせず各段を連続して計算できます。どちらの配置も、根の0段目は`-1`を保ち、高段は成分根で止めます。

GCCの浅い森の祖先照会では、移動量kの上位ビットから上ります。大きな移動を先に行い、次の照会を根に近い頂点へ寄せます。先にkが深さ以下であることを確認するため、ビットを使う順序によらず根を越えず、移動量の和はkになります。

入力グラフの参照は保持しません。`build`とコピー代入は、新しい表が完成してから交換するため、検査や確保で例外が出ても元の内容を保持します。コピー後の再構築・破棄は互いに影響しません。頂点情報と親の表は各オブジェクトが所有し、深い森の不変な照会表は`shared_ptr<const ...>`で共有します。ムーブ後の元は空で再利用可能です。自己コピー・自己ムーブは内容を保持します。

検査有効時は、参照した頂点番号、不正な根、閉路・多重辺で例外を投げます。隣接リストの対称性は検査しません。`SKIP_RUNTIME_CHECKS`で入力検査を除外した場合も、頂点数・祖先表・補助配列の容量オーバーフロー対策は維持します。

## 照会

| API | 戻り値 | 計算量 |
| --- | --- | --- |
| `LCA()` / `LCA(g,root=0)` | 空の表 / gから構築した表。 | O(1) / 構築と同じ |
| `build(g,root=0)` | 入力から再構築する。 | 構築と同じ |
| `size/empty/component_count/root` | 頂点数・空判定・成分数・指定根。空の根は-1。 | O(1) |
| `parent/depth_of/component_of/root_of(v)` | 親・深さ・成分番号・成分根。根の親は-1。 | O(1) |
| `same_component(u,v)` / `is_ancestor(u,v)` | 同成分か / uがvの祖先か。自身も祖先に含む。 | O(1) |
| `get(u,v)` / `operator()(u,v)` | 構築時の根に対する最近共通祖先。異成分なら-1。 | O(1) |
| `get(u,v,new_root)` | new_rootを根とした最近共通祖先。3頂点の成分が揃わなければ-1。 | O(1) |
| `get_distance(u,v)` | パスの辺数。異成分なら-1。 | O(1) |
| `kth_ancestor(v,k)` | k個上の祖先。k=0ならv、根を越えると-1。 | O(log(H+2)) |
| `kth_on_path(u,v,k)` | uからvへのパスのk番目（0始まり）。異成分・範囲外なら-1。 | O(log(H+2)) |
| `order_index(v)` | 森全体でのDFS順添字。 | O(1) |
| `subtree_range(v)` / `subtree_size(v)` | DFS順の部分木半開区間 / 部分木の頂点数。 | O(1) |
| `clear()` / `swap(other)` | 領域を解放して空にする / 内容を交換する。 | O(N+B log(B+1)) / O(1) |

照会の頂点番号は表の範囲内である必要があります。kは`std::uint64_t`で受け取り、`UINT64_MAX`でも範囲外を正しく判定します。根変更の`get`は結果だけを計算し、表や部分木の向きを変更しません。森の最大深さが1以下なら、成分検査後に3頂点の一致を判定するだけで答えを求めます。

## 部分木の区間と祖先探索

DFS順添字は全N頂点から`[0,N)`への全単射です。`subtree_range(v)={first,last}`とすると、vの部分木は`first <= order_index(x) < last`を満たす頂点全体です。`last-first`は`subtree_size(v)`に一致します。兄弟の訪問順は規定しません。頂点ごとの値をこの添字で配列に並べれば、部分木を区間として処理できます。

LCAの照会では、異成分を除いた後、DFS順が小さい側をuとします。vの添字がuの部分木に入ればuを返します。浅い森では最大9段の祖先表を使い、vを部分木に含まない祖先までuを引き上げ、その親を返します。

GCCでは、単一木の根の子部分木を分けるDFS境界を1つ保存します。祖先関係にない2頂点がこの境界の両側にあれば、LCAは根なので祖先表やRMQの探索を省けます。境界はDFS中央の頂点が属する根の子部分木を求め、その両端から左右の頂点数が最も均等になる方を選びます。小さい木・根の子が1つの木・偏りの大きい分割・森では使いません。元の頂点番号や隣接リストの順序には依存せず、頂点数に比例する追加配列も必要ありません。

根の子が2つなら、それぞれの子部分木にも同じ方法で境界を1つずつ保存します。根の境界をまたがない照会は片方の子部分木に属するため、その内側の境界をまたげば答えはその子です。追加状態は境界2つと対応する祖先・有効判定だけで、前処理は祖先照会最大2回分です。小さな部分木や偏った分岐では内側の境界を使いません。

深い森では、DFS順でa=entry(u)<b=entry(v)とすると、区間(a,b]に現れる頂点の「親のDFS順添字」の最小値がLCAの添字になります。区間の各頂点の親はLCAの部分木内にあり、vへ向かう子部分木に入る位置では親がLCAになります。このため元の頂点番号の大小や、根が0であることに依存しません。

RMQは32要素のブロックに分け、ブロック内の単調スタックを32-bitのマスクとして各位置に保存します。区間終端のマスクから区間開始より前のビットを除き、最下位の1ビットで最小値の位置を得ます。ブロック間はブロック最小値の疎テーブルを使います。中央の完全なブロックだけで成分根が見つかれば、それより小さい答えはないため両端の照会を省けます。

祖先の照会では、各頂点から最も長く下れる子を選んでパスへ分け、各パスを自身の長さまで上へ延長して連続配列に置きます（Ladder分解）。延長を含む全長は2N以下です。照会は配列内で直接答えるか、延長の先へ移ります。後者では次に使うパスの長さが少なくとも倍になるため、O(log(H+2))回で終わります。構築の作業配列はDFSの作業領域を再利用します。

Ladderの数学的な参考は[Bender・Farach-Colton, The Level Ancestor Problem Simplified](https://www3.cs.stonybrook.edu/~bender/newpub/2004-level.pdf)です。コードの出典ではありません。

[RMQ境界・任意ラベルの試験](../Verify/current/tests/lca_rmq_branch_test.cpp)は、32/64要素付近の境界、深さ255〜258、長鎖・櫛形・深い分岐森を親列の参照と照合します。[対応する確保失敗試験](../Verify/current/tests/lca_rmq_allocation_test.cpp)では、深い森の構築・コピー・再構築と共有表の寿命も確認します。

[浅い大規模森の試験](../Verify/current/tests/lca_shallow_label_test.cpp)は、乱択木・二分木・森の頂点番号と隣接順を入れ替え、任意の根から親列によるLCA・距離・祖先・パス・根変更を照合します。2の累乗付近の頂点数と、コピー後の元オブジェクトの再構築・破棄も扱います。

[根付近で分岐する木の試験](../Verify/current/tests/lca_root_cut_test.cpp)は、根の子部分木の境界前後、小さい木、偏った分岐、深い2本の枝、長い幹の先の分岐、森を独立した親列の参照と照合します。[確保失敗試験](../Verify/current/tests/lca_root_cut_allocation_test.cpp)は、浅い木・深い木・森の間の再構築とコピーの例外保証も確認します。
